# UI / UX Audit — visa4bali.com

**Audited:** 2026-08-15 · **Method:** live Chrome DevTools, no assumptions — every number below measured on the live site.
**Viewports:** 360×800, 390×844 (iPhone 14), 768×1024 (tablet), 1440×900 (desktop).
**Pages:** `/`, `/about-us/`, `/our-services/`, `/contact-us/`, `/shop/`, `/product/d1-d2-visa-extension/`.

Severity: 🔴 blocks use / loses money · 🟠 visible flaw · 🟡 polish.

---

## Summary

Desktop layout is broadly sound (no horizontal scroll at 1440). **Mobile is where the site is untidy** — and mobile is the main traffic source.

Three root causes explain most of the mess:

1. **Desktop values never overridden at mobile breakpoint** — 48px hero font, 160px section padding, 230px-wide contact form.
2. **No spacing system** — left gutters land on 8 different values (18/25/35/37/40/45/50/55px) on one page. Eyes read this as "not rapi" even when nothing is technically broken.
3. **Three different page shells** — Elementor pages, WooCommerce shop (raw theme), product pages (third footer variant). Site looks like three sites.

## 🔴 Critical

### 1. Horizontal scroll on every Elementor page — mini-cart overflows

| Viewport | Document width | Overflow |
|---|---|---|
| 360px | 373px | **+13px** |
| 390px | 401px | **+11px** |

Isolated by hiding elements one at a time: **`.elementor-menu-cart__toggle_wrapper` alone causes 100% of it** (`right: 402px` on a 390px viewport). Hiding it → scrollWidth drops to exactly 390. The "To Travel to Bali" heading is *not* the scroll cause (it is clipped by an overflow-hidden ancestor), though it is its own bug — see #2.

Affects `/`, `/our-services/`, `/product/*` — every page with the cart widget.

```css
@media (max-width: 767px){
  .elementor-menu-cart__toggle_wrapper{
    max-width: calc(100vw - 30px);
    margin-right: 0;
  }
  .elementor-menu-cart__toggle .elementor-button{ padding-right: 8px; }
}
```

Same bug was logged 2026-05-28. Still open.

### 2. Hero H2 "To Travel to Bali" is cut off on mobile

Measured: `font-size: 48px`, widget width **749.5px** inside a 390px viewport. Renders as `To Travel to Bal|` — the last letter is sliced off mid-glyph. H1 above it ("Apply for a Visa", also 48px) wraps fine because its widget is not width-locked.

On desktop the two form one line: *"Apply for a Visa To Travel to Bali"*. On mobile that intent breaks.

Fix in Elementor → heading `a3ec264` → Style → Typography → **Mobile: 28–30px**, and Advanced → Width: remove the `initial`/fixed width for mobile.

### 3. WhatsApp float widget covers the primary CTA

The "Need Help? **Chat with us**" bubble sits bottom-right and **overlaps the `EXPLORE NOW` button** in the mobile hero (verified in screenshot at scroll 0). On `/our-services/` it covers the "* Tax & other services included" line under the pricing card.

Fix: shrink to icon-only on mobile (hide the text bubble under 768px), or raise `bottom` offset so it clears CTAs.

### 4. Mobile menu has no "Contact Us"

Desktop nav: HOME · ABOUT US · OUR SERVICES · **CONTACT US** · Cart.
Mobile nav (`#menu-header-menu`, jkit off-canvas): **HOME · ABOUT US · OUR SERVICES** — that's it.

Header is built as two separate Elementor sections with two different menus assigned. Mobile visitors cannot reach `/contact-us/` from navigation at all.

### 5. Contact page — phone and email are not tappable

`/contact-us/` measured: `a[href^="tel:"]` = **0**, `a[href^="mailto:"]` = **0**.
The phone number `(+62) 87862273133` and `info1visaforbali@gmail.com` are plain text. On a phone, a visitor cannot tap to call or mail.

Footer is worse — the address, phone, email and opening hours are all `<a href="#">`, i.e. clickable-looking links that do nothing.

### 6. Contact form is 230px wide on a 390px screen

| Element | Width |
|---|---|
| Viewport | 390px |
| Form widget | **230px** (left edge at 80px) |
| Every input | **170px** (left edge at 110px) |

41% of screen width wasted; inputs are half the usable width. Desktop column padding was never reset at mobile. Textarea 170×180, submit button 170×44.

Fix: Elementor → that column/section → Advanced → Padding → **Mobile: 20px left/right**, and set the form widget width to 100%.

## 🟠 High

### 7. Left gutter is ragged — no spacing system

Left edge of every visible Elementor widget, counted per page at 390px:

| Page | Left-edge values (count) |
|---|---|
| `/` | 25(3) · **35(19)** · 36(1) · 40(2) · 45(1) · **50(28)** · 55(2) · 90(4) |
| `/about-us/` | 18(14) · 35(10) · 37(6) · 40(2) · 49(1) · **50(80)** · 55(1) · 70(6) |
| `/contact-us/` | 35(3) · 40(2) · 45(1) · 50(8) · 55(1) · **80(11)** · 95(1) · **110(12)** |
| `/our-services/` | 25 · 35(3) · 40(3) · 45 · **50(39)** · 55(2) · 76(12) · 91(6) |

Right edges are equally split (355 / 340 / 320). This is the single biggest driver of "looks untidy" — content starts at a different x-position every few sections.

**Fix:** pick **one** mobile gutter (recommend 20px page padding → content at x=20, width 350) and apply it as section padding site-wide. Delete per-widget left/right padding and negative margins.

Worst single offender on `/`: the About section icon-boxes — icon at x=50, its heading at x=68, its body text back at x=50. Ragged inside one component.

### 8. Section spacing is arbitrary

Measured `padding-top` / `margin-top` on homepage top-level sections at 390px:

| Section | padding-top | padding-bottom | margin |
|---|---|---|---|
| Hero `6fd792fa` | **160px** | 100px | — |
| `41cd78b2` | 0 | 0 | **-20px** top |
| `7524b616` | 40px | 40px | **-60px** top |
| `4f02eb8b` | 0 | 60px | — |
| `3a8640a4` | 0 | 40px | — |
| `5833f92` | 60px | 20px | — |
| `1fcfc75c` | 60px | 0 | — |
| `146b94a` | 0 | 0 | **-100px** bottom |
| `61463a8e` | **160px** | 40px | — |

Nine sections, nine different rhythms, plus three negative margins used to claw back space that shouldn't have been added. The 160px hero top-padding is what pushes the value proposition below the fold on mobile.

**Fix:** standardise mobile section padding to `56px` top/bottom (or 40/64 two-step scale), remove all negative margins.

### 9. About Us page is 16,897px tall on mobile

That is ~20 full screens. Cause: **20 team members stacked one per row**, each ~570px tall.

Fix: team grid → Mobile columns = **2**. Halves the page to ~9,000px. Or show 6 key staff and put the rest behind "View full team".

### 10. About Us — team photos overflow their containers

10 widgets measured with `right` between **418 and 437px** on a 390px viewport. No document scroll (clipped by ancestor), but photos are cropped asymmetrically — faces sit off-centre.

Fix: those image widgets have a fixed 400px width; set `max-width:100%` / remove the fixed width at mobile.

### 11. Tap targets below 44×44px

26 on `/`, 31 on `/our-services/`, 20 on `/about-us/`. Worst offenders:

| Element | Size | Note |
|---|---|---|
| Hamburger `open-menu` | **26×24** | primary navigation control |
| `SERVICE DETAIL` ×3 | 139×**15** | main service CTA |
| `WATCH INTRO` | 104×**12** | |
| Footer links (About/Visa/Contact/…) | 277×**21** | 8 of them |
| Footer social icons | 38×38 | |
| Product `ADD TO CART` | 142×**35** | the purchase button |
| FAQ accordion rows | 290×**23** | |

Apple minimum 44×44, Android 48×48.

### 12. Shop and product pages use a different design system

`/shop/` renders with the **raw hello-elementor theme**: plain text wordmark "Visa4Bali", tagline "Best Visa Agency in Bali", a hamburger with no styling, **no site footer at all**, default WooCommerce typography. No logo, no brand colours, no contact info.

`/product/d1-d2-visa-extension/` has the Elementor header back, but a **third footer variant** — centre-aligned, different link order (Contact Info → Support → Quick Links), and different social icons (adds Twitter + YouTube, which the homepage footer doesn't have).

So a visitor going Home → Shop → Product sees three different sites. This is the most visible "not rapi" problem after the gutters.

### 13. Product page is bare, and off-brand

- `ADD TO CART` background is `rgb(127, 84, 179)` = **WooCommerce default purple `#7F54B3`**, radius 3px. Site buttons elsewhere are blue/navy pills. It is the only purple element on the site.
- Button is 142×35 — under tap-target minimum, for the money button.
- No breadcrumb, no product description, no tabs (`.woocommerce-tabs` = 0 items).
- Category shows **"Uncategorised"**.
- Product image is a **screenshot of a price list** — unreadable at thumbnail size, and unreadable at full mobile width too.

### 14. Shop shows 2 products per page → 6 pages for 12 products

`"Showing 1–2 of 12 results"` with pagination 1-2-3-4-5-6. Same as May audit, unchanged.
Fix: WooCommerce → Settings → Products → Display → rows/columns to yield 9–12 per page. Product cards measured 178px wide in a 2-up grid — that grid is fine, there just aren't enough items in it.

### 15. Six of eight footer links go nowhere

Verified by HTTP status:

| Footer link | Target | Status |
|---|---|---|
| About | `#` | — (page `/about-us/` exists, link not wired) |
| Visa | `#` | `/visa/` → **404** |
| Coaching | `#` | `/coaching/` → **404** |
| Pricing | `#` | `/pricing/` → **404** |
| Contact | `#` | `/contact-us/` exists, link not wired |
| Support | `#` | `/support/` → **404** |
| Privacy Policy | `#` | `/privacy-policy/` exists, link not wired |
| Terms & Conditions | `#` | `/terms-and-conditions/` → **404** |

14 dead `href="#"` links per page, including the hero **`EXPLORE NOW`** — the single most prominent CTA on the site points nowhere.

### 16. Content is hidden until JavaScript loads

WP Rocket "Delay JavaScript Execution" holds **50 scripts** as `type="rocketlazyloadscript"`. Before any user interaction: `jQuery` = undefined, `elementorFrontend` = undefined, and **16 widgets sit at `visibility: hidden`** waiting for their fadeIn animation — including all three service cards and four section headings.

Result on a slow connection: the homepage shows a **~1,100px blank white gap** between the partner logos and the About section. Verified by screenshot. Once JS loads (first touch triggers it) everything appears correctly.

Also affected: the contact form does not exist in the DOM until JS runs (0 `<form>` before, 1 after).

**Fix options:** exclude Elementor's animation-critical scripts from delay, or remove entrance animations on mobile entirely (they cost more than they add on a 4-inch screen).

## 🟡 Medium

### 17. Body text is 14px

Font-size histogram across homepage text nodes: **14px ×155**, 12px ×7, 10px ×1, 16px ×3, 18px ×4.
14px is below the 16px mobile-readability convention; 10–12px items (partner logo labels, helper text) are hard to read at arm's length.

### 18. Heading scale is inconsistent

Same-level headings render at different sizes: H2 at **48px** (hero), **32px** (four section titles), **28px** ("We Provide An Easy Process"). H5 used both for 11px eyebrow labels and a 16px card title. One font family throughout (Plus Jakarta Sans) — good — but no size scale.

### 19. Container max-width varies between sections (desktop)

Measured at 1440: `1270px` ×5, `1290px` ×8, `1310px` ×1. Section edges shift up to 20px between neighbouring sections. Visible as a slightly wobbling left margin when scrolling.

### 20. Cart shows "Rp0" when empty

Header cart reads `Rp0 / 0 / Cart` on every page. Reads like a price tag. Unchanged since May.

### 21. Broken icon-font labels

- Footer: link text is literally **"Jki-facebook-f"** instead of "Facebook".
- `/contact-us/`: **"Jki-facebook-light"** plus a stray glyph `ףּ` rendering where the Facebook icon should be.

Screen readers announce the class name; the contact page shows visible garbage characters.

### 22. About Us — 20 empty headings, 46 images with no alt

Unchanged from May audit. Empty `<h1>`–`<h6>` widgets used as spacers.

### 23. Second Google Map is unlabelled

`/contact-us/` embeds two maps:
1. `Jl. Pantai Balangan, Jimbaran, Badung, Bali`
2. `J2WR+4W Gili Indah, North Lombok Regency, West Nusa Tenggara`

**Confirmed by owner 2026-08-15: the Lombok location is a real branch — keep it.** Problem is that neither map carries a heading, so a visitor sees two maps 150km apart with no explanation. Add a location label above each ("Bali Office — Jimbaran" / "Lombok Branch — Gili Indah") plus its own address block.

### 24. Slider ARIA is garbled

Partner logo carousel announces `"slide 17 to 18 of 5"`. Unchanged since May.

### 25. Mobile shows fewer partner logos than desktop

Desktop: 4 partner logos (LPD, V4B Jakarta, V4B Luwuk, V4B Jaktim). Mobile: 2 visible, at ~10px text height — illegible either way.

### 26. Tablet (768px) leaves half the hero empty

The hero photo is hidden at 768px but the two-column layout stays, leaving a blank right half ~380px wide next to the headline.

### 27. CTA colour changes by breakpoint

`EXPLORE NOW` is dark navy on desktop, bright blue on tablet and mobile. Same button, two brand colours.
